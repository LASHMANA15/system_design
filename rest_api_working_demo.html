REST API — Interactive Working Demo

A simple user-management example showing how a client sends an HTTP request and receives a response from a server. This is a front-end simulation; it does not connect to a real backend.

System flow
1. Client / BrowserSelect an operation and send a request
→
2. REST API ServerReceives HTTP method and resource path
→
3. User DataServer reads or updates user records

The server then sends an HTTP response back to the client, usually with a status code and data such as JSON.

Why it is REST

Resource /api/users/101 identifies a user resource.

HTTP method GET, POST, PUT, and DELETE describe the action.

Representation The server can send the user’s current data as JSON.

Transfer The representation travels between client and server in the HTTP response.

For a real REST API, a backend server must implement these routes. This demo only illustrates the request/response flow for a lab explanation.
